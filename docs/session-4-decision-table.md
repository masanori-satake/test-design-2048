# Session 4: デシジョンテーブルを用いた複雑な仕様の整理

## 1. 学習目的
* 条件が複雑に絡み合うビジネスロジックに対して、デシジョンテーブル（決定表）を作成して整理する手法を修得する。
* `src/game_manager.py` の `is_game_over(board)` 関数の判定条件を整理し、テストケース漏れを防ぐ。

## 2. 現場での悩み
> 「`if` 文が重なった複雑な判定ロジックで、どの条件の組み合わせをテストしたのか分からなくなります...」
> 「仕様の条件漏れがあり、特定の盤面状態（例: 空きはないが隣り合う同じ数値がある）でバグが発生しました...」

## 3. 演習指示
1. **仕様の確認**:
   * `is_game_over(board)` は以下の2つの条件を両方満たす場合に `True` を返します。
     * 条件A: 盤面に空きマス（0）が存在しない。
     * 条件B: 上下左右に隣接する同じ数字が存在しない（動かせる手がない）。
2. **デシジョンテーブルの作成**:
   * 条件A (True/False) と 条件B (True/False) の組み合わせによる期待結果（True/False）を表として整理します。
   * **📝 ワークシート記入**: `docs/worksheets/participant_test_design_worksheet.md` の **「テスト設計 2: 組合せテスト（デシジョンテーブル / ペア構成法）ワークシート」** の各項目（2-1〜2-3）を埋めて、デシジョンテーブルを完成させてください。
3. **テスト実装**:
   * `tests/test_game_manager.py` にデシジョンテーブルの各行に対応するテストケースを実装してください。

## 4. 振り返りの問いかけ
* デシジョンテーブルを作成したことで、漏れていた判定条件（例: 盤面は埋まっているが横方向に合体可能なマスがある状態）を事前に発見できましたか？

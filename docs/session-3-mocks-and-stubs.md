# Session 3: モックとスタブの活用

## 1. 学習目的
* ランダム性や外部依存を持つコードのユニットテスト手法を学ぶ。
* `unittest.mock` (`patch`, `MagicMock`) や `pytest-mock` を使用して、テスト結果を決定論的（Deterministic）にする。
* `src/tile_generator.py` の `spawn_tile` 関数のテストを設計・実装する。

## 2. 現場での悩み
> 「ランダムな値や現在時刻、外部API呼び出しに依存するコードのテストが時々失敗（Flaky Test）してしまいます...」
>
> 「モックを使いすぎて、何をテストしているのか分からなくなってしまいました...」

## 3. 演習指示
1. **仕様の確認**:
   * `spawn_tile(board)` は盤面内の空きマス（`0`）を1つ選択し、90%の確率で `2`、10%の確率で `4` を生成します。
2. **モック化のポイント設定**:
   * `random.choice` をモック化して、タイルが生成される位置を固定します。
   * `random.random` をモック化して、`2`（例: 0.5）または `4`（例: 0.95）が生成される分岐を固定します。
   * **📝 ワークシート記入**: `docs/worksheets/participant_test_design_worksheet.md` の **「テスト設計 3: 状態遷移テストワークシート」** を活用し、モックを用いて状態（Game Over状態への遷移など）をどう固定するか整理してください。
3. **テスト実装**:
   * `tests/test_tile_generator.py` にモックを用いたテストを追加してください。
   * 盤面に空きマスがない場合、入力を変更せず盤面のコピーがそのまま返されること（不変挙動）を検証してください。

## 4. 振り返りの問いかけ
* モックを使用することで、何回実行しても100%成功する確定的なテストになりましたか？
* 実装の詳細に依存しすぎた過剰なモック化になっていませんか？

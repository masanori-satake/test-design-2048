# Session 1: ユニットテストの基本と仕様の理解

## 1. 学習目的
* ユニットテスト（単体テスト）の基礎概念と重要性を理解する。
* AIツールが出力したテストコードをそのまま鵜呑みにせず、仕様に基づいて評価できる視点を養う。
* pytest の基本構文と実行方法を習得し、`src/board_logic.py` の仕様を満たすテストコードを作成できる。

## 2. 現場での悩み
> 「生成AIに『テストを書いて』と頼むと一瞬で生成してくれますが、そのテストが本当に対象関数の全仕様やエッジケースをカバーしているのか判断できません...」
>
> 「仕様変更があったとき、テストコードのどこを直せば良いのか追えなくなってしまいました...」

## 3. 演習指示
1. **仕様の確認**: `src/board_logic.py` にある `is_board_full(board)` 関数の仕様を確認します。
2. **テストパターンの洗い出し**:
   * 盤面の状態としてどのような入力パターンがあり得るか（空きマスあり、空きマスなしなど）をノートやスプレッドシートに書き出します。
   * **📝 ワークシート記入**: `docs/worksheets/participant_test_design_worksheet.md` の **「テスト設計 1」** 内にある **「`is_board_full` 用テストケース」** の表を活用して、テストする条件を整理してください。
3. **テスト実装**:
   * `tests/test_board_logic.py` に記述されているサンプルテスト (`test_is_board_full_returns_true_when_full`) を参考に、`is_board_full` の仕様を満たす追加のテストケースを実装してください。

## 4. 振り返りの問いかけ
* 作成したテストコードは「実装の動作」ではなく「仕様」を検証できていますか？
* AIが出力したテストケースに対して「このテストケースはなぜ必要なのか」を説明できますか？

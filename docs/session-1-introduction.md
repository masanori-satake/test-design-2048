# Session 1: ユニットテストの基本と仕様の理解

## 1. 学習目的
* ユニットテスト（単体テスト）の基礎概念と重要性を理解する。
* AIツールが出力したテストコードをそのまま鵜呑みにせず、仕様に基づいて評価できる視点を養う。
* pytest の基本構文と実行方法を習得し、`src/board_logic.py` の仕様を満たすテストコードを作成できる。

## 2. 現場での悩み
> 「生成AIに『テストを書いて』と頼むと一瞬で生成してくれますが、そのテストが本当に対象関数の全仕様やエッジケースをカバーしているのか判断できません...」
> 「仕様変更があったとき、テストコードのどこを直せば良いのか追えなくなってしまいました...」

## 3. 演習指示
1. **仕様の確認**: `src/board_logic.py` にある `is_board_full(board)` 関数および `slide_and_merge_line(line)` 関数の仕様を確認します。
2. **テスト設計表の作成**:
   * どのような入力パターンがあり得るか（空きマスあり、空きマスなし、サイズが異なる盤面など）をノートやスプレッドシートに書き出します。
3. **テスト実装**:
   * `tests/test_board_logic.py` に記述されているサンプルテスト (`test_is_board_full_returns_true_when_full`) を参考に、追加のテストケースを実装してください。
   * `slide_and_merge_line` に対するテスト関数を作成してください。

## 4. 振り返りの問いかけ
* 作成したテストコードは「実装の動作」ではなく「仕様」を検証できていますか？
* AIが出力したテストケースに対して「このテストケースはなぜ必要なのか」を説明できますか？
